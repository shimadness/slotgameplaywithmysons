# TRIPLE SLOT

息子たちと遊ぶために作った、ブラウザ用スロットゲーム。
ゲームの遊び方や演出は、ゲームセンターのメダルゲームの挙動を参考にさせてもらっていますが、
グラフィック・効果音・配当・ロジックはすべて独自実装で、外部の画像/音源・著作物は一切使っていません。
Vite + TypeScript 製で、サーバー不要・ローカルだけで動きます。

「**パズル × スロット**」の連鎖ゲーム（3×3 DROP）と、王道の **5リール** スロットを
モード切替で遊べます。

## ゲーム内容

ヘッダーの **モード切替** で2種類を切り替えられます。

### ① 3×3 DROP（連鎖パズル × スロット）

- **3×3グリッド**。同じシンボルが **3つ以上つながると配当**（クラスター判定）。
- つながり方は **「道（通路）」** で決まる：**タテ・ヨコは常に接続、ナナメは中央マスに
  つながる場合のみ**。揃うと、つながった道がシンボル色に**点灯**して見える化される。
- 揃ったシンボルは消え、上から新しいシンボルが**ぷよぷよ風に落下**（重力加速＋着地の潰れ）
  → 再判定で **連鎖**。連鎖が伸びるほど **倍率UP**。
- **NEXT プレビュー管**：各列の上に「次に落ちてくる」シンボルを先読み表示。管からそのまま
  盤面へ滑り込む連続演出。
- **リール回転スピンイン**：出目はいきなり出ず、各列が回転してから左→右に停止
  （速度連動モーションブラー＋停止音）。
- **ワイルドファイブ ✨**：任意のシンボルを代用するワイルド。**消えずに最大5回使える**
  （残り回数を表示。使うたび -1 して落下、5回使い切ると消滅）。
- **連鎖を多く重ねると RUSH 突入**（フリープレイ＋配当倍率、連鎖でさらに上乗せ）。

### ② 5リール

- **5リール × 3段 / 10ライン**。左から連続で揃うと配当。
- **スキャッター 🌟 3個以上で RUSH（フリースピン）** 突入。個数で回数・倍率が変化。
- **リーチ演出**：4本目停止時に「2スキャッター」or「高配当4連」を検出すると、
  最終リールを引き伸ばして点滅＋緊張音で煽る。

### プレイヤー（3人別々のクレジット）

- 起動時に **「だれが あそぶ？」** でプレイヤーを選択（3人分）。名前はその場で変更可。
- 各プレイヤーは **クレジット・ベット・設定が完全に別々**（端末内に個別保存）。
- ヘッダーの **👤 ボタン** でいつでも切り替え。各自のスマホで自分の名前を選べばOK。
- ※サーバーを使わない構成のため、クレジットは**端末ごとに保存**（端末間では同期しません）。

### 共通

- **効果音**：Web Audio ですべて合成（音源ファイル不要）。🔊 で消音切替。
- **RUSH 専用 BGM ＆ 背景演出**：RUSH中はループBGMが鳴り、背景が熱色に変化＋放射状の光が回転。
- **オートプレイ**：AUTO で自動連続プレイ。残高不足で自動停止。
- **クレジット/ベット**：BET▲ でベット変更、MAX BET、残高は localStorage に自動保存。
  残高不足で「+1000」補充ボタンが出ます。

### ペイアウト率（設定 1〜6）

ゲーセンの「設定」のように、**ペイアウト率（RTP）を設計値として持つ**仕組み。

- ヘッダーの **「設定」** ボタンで **1〜6** を切替（90% / 92% / 94% / 95% / 96% / 97%、既定は4＝95%）。
- 配当は内部で `目標RTP ÷ 基準RTP` の係数を掛けて、狙ったRTPに合わせ込んでいる。
- RTPは計測ハーネスで実測できる：

```bash
npm run rtp          # 既定スケールで計測
npm run rtp 0.146    # スケールを指定して計測
```

## RTDB ルール

ランキング・大会・バグ報告・アプリ更新告知は Firebase Realtime Database（プロジェクト
`triple-slot-ranking`）を使う。ルールの正本は [`docs/rtdb-rules.json`](docs/rtdb-rules.json)。

| ノード | 誰が | できること |
|---|---|---|
| `drop` / `slot` | 誰でも | 読む・新しい記録を足す（消す・書き換えるのは不可） |
| `events/<CODE>` | 誰でも | 読む・大会の進行（作成→開始→終了／中断、参加・報告・退出）。進行中の大会のリセットや開始時刻・初期メダル・ホストの変更、速報の改ざん、大会ごとの削除は不可 |
| `bugreports` | 誰でも | 書くだけ（1端末60秒に1件・読めない） |
| `appmeta` | 誰でも | 読むだけ（Firebase コンソールから手で更新） |
| `typing` | — | **別ゲーム（Type Heroes）のデータ**。同じ DB に同居しているので、ルールは消さずに残す |

ログインの仕組みが無いので「本人かどうか」はルールで判定できない（他人のスコアの
書き換え、ありえない高スコアの登録、あいことばを知っている人による中断などは防げない）。

**反映のしかた**: Firebase コンソール → Realtime Database → 「ルール」タブ →
エディタの中身を `docs/rtdb-rules.json` の内容に置き換えて「公開」。
公開前に今のルールをテキストに控えておくと、戻したいときに貼り直せる。

## 🐞 バグ報告（アプリ内 → GitHub Issue）

ヘッダーの **🐞 報告** から送ると、次の流れで GitHub Issue になります。

```
アプリ（フォーム）
  │  分類・本文 ＋ 自動添付（バージョン/コミット・端末・ゲーム状態・直近のJSエラー）
  ▼
RTDB bugreports/<id>     ← クライアントは「書き込み専用・作成のみ」
  │  .github/workflows/bugreports.yml（毎時23分・手動実行も可）
  ▼
GitHub Issue（labels: bug-report, triage-needed, [has-js-error]）→ RTDB からは削除
```

GitHub のトークンはクライアントに持たせず、Actions 側が取りに行く方式です
（Spark プランでは Cloud Functions が使えないため）。

### いたずら・連投への対策（第1段階）

| 場所 | 対策 |
|---|---|
| RTDB ルール | 読み取り不可／上書き・削除不可／文字数上限／決まった項目以外は拒否／時刻はサーバー時刻のみ／**1端末60秒に1件** |
| 変換スクリプト | 1回の実行で最大20件／**同じ端末は1回の実行で3件まで**（超過分は破棄）／未トリアージが30件以上なら作成を一時停止 |
| Issue 本文 | 報告文はコードブロックに入れる（メンション・リンク・HTML を無効化）。「未検証の外部入力」と明記 |
| 個人情報 | プレイヤー名は送らない。端末IDは乱数で、Issue にはハッシュだけを載せる。**リポジトリが public なので Issue も公開される**（フォームに「名前は書かないで」と表示） |

修正の自動化はまだしていません（Issue 化まで）。

### セットアップ（初回のみ）

1. **RTDB ルールを反映**: 下の「RTDB ルール」の手順で公開する。
2. **サービスアカウント鍵を作る**: Firebase コンソール → プロジェクトの設定 →
   サービス アカウント → 「新しい秘密鍵の生成」で JSON をダウンロードする。
3. **GitHub Secret に登録**: リポジトリの Settings → Secrets and variables → Actions →
   New repository secret で、名前を `FIREBASE_SERVICE_ACCOUNT`、値を JSON の中身すべてにする。
4. **動作確認**: Actions → 「Bug reports → Issues」→ Run workflow（`dry_run` にチェックを
   入れると Issue を作らずにログで内容だけ確認できる）。

Secret が未設定の間、このワークフローは何もせず成功で終わります。
